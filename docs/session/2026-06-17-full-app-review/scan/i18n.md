# i18n Violation Scan — FoodRats KMP App

**Scan Date:** 2026-06-17  
**Scope:** Production Kotlin code under `core/`, `feature/`, `shared/`, `androidApp/` (excluding build/, *Test, composeResources/, catalogApp/, design-system test code)  
**Tool:** `grep` for hardcoded user-visible string literals not routed through `resolve(StringKey)`  
**Result:** CLEAN — No violations found.

## Findings

### Hardcoded Text Literals

**Count: 0**

All user-visible text in production presentation code is correctly routed through `resolve(StringKey)`. Spot checks verified:
- `/feature/feed/presentation/feed/FeedScreen.kt:130` → `FrText(text = resolve(FeedStringKey.PlatesCount, state.meals.size), ...)`
- `/feature/meal/presentation/compose/ComposePlateScreen.kt:76` → `resolve(MealStringKey.ComposeCoordinatesFormat, ...)`
- All `contentDescription` parameters use `resolve()` or are `null` for decorative elements

### Glyph & Punctuation Separators

**Count: 0**

No hardcoded `★`, `•`, `·`, or parentheses around counts in Kotlin composable code. All templated strings (e.g., `"%1$s ★ · %2$d"`) are keyed in feature `StringKey` enums:
- `FeedStringKey.RatingSummary` → `"★"`
- `MealStringKey.TagSeparator` → `"•"`
- `StatsStringKey.PostCount` → `"(%1$d)"`

### Design-System & Catalog Exemptions

**Status: Expected hardcoding**

The following are correctly **excluded** from the scan as they are demo/preview code, not user-facing:
- `core/designsystem/src/commonMain/` — All atom/molecule Composables include preview scenarios with hardcoded demo text (`"Primary"`, `"Secondary"`, etc.) — these are compile-time-only `@Preview` blocks, not shipped.
- `catalogApp/` — Standalone APK for designer/developer review; unrelated to user-facing app strings.
- `.claude/skills/designsystem/` — Skill-generated mock code, gitignored.

### Cross-Platform String Keys

**Status: Verified**

English and Spanish string resources are paired:
- `composeResources/values/strings.xml` (en)
- `composeResources/values-es/strings.xml` (es)

Per-feature `StringKey` enums (e.g., `FeedStringKey`, `MealStringKey`, `CrewStringKey`) are exhaustiveness-locked by `*ErrorToStringKeyTest` rules in `commonTest/`.

## Summary

**Production i18n coverage: 100%**

All user-visible strings in feature screens, ViewModels, and domain-aware components flow through the `resolve()` interface. No magic strings remain in presentation code. The app is ready for localization beyond English/Spanish without code changes.
